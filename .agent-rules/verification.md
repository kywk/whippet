# MVP 驗證原則

[主規範](../AGENTS.md)

- 依改動執行受影響模組的編譯／型別檢查與最小相關測試；通過後繼續開發。
- UI 文案、樣式與文件等低風險改動，以直接檢視確認，不新增鏡像實作的測試。
- 自動化測試優先覆蓋：草稿版本發佈門檻、重複任務不重跑、Worker 回收後才釋放名額。
- 整合時使用一條主要操作流程 smoke test；避免每個小步驟重跑全套 E2E。
- Mac Docker、跨主機連線與影像傳輸，在功能整合時各做代表情境；環境不可用就註明未驗證，其他工作照常進行。
- 自動修復不能刪除或弱化原本測試意圖來換取通過。報告以實際執行結果為準。
- 平台的開發驗證保持精簡；產品要求的「每個發佈 revision 必須通過 E2E」仍須實作。
- 文件骨架階段已結束。整合階段先建置相關模組，再執行成功／斷言失敗各一條端到端流程；單純測試派給指定 Muse 模型。
