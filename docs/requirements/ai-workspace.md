# AI 對話工作區規格

2026-11-12 使用者已同意；本文件定義目標行為，不表示已實作。進度只在 [實作計畫](../tracking/implementation.md) 維護。

## 對象與完成條件

不懂 Playwright 的 QA 能透過 AI 建立、修改、驗證與發佈測試；不必手寫腳本。保留 QA 明確確認發佈。本輪登入先支援帳密表單，不包含 SSO、MFA、驗證碼或人工遠端接管。

## 測試一般模式

概覽採左右兩欄。左欄依序顯示腳本說明與執行歷史，其中包含目前正式版本與最近執行結果。右欄依序顯示標籤、唯讀腳本內容與版本歷史。歷史版本詳情標示所選版本，正式執行使用目前發佈版本。

- 開啟已發佈測試時顯示概覽。點擊「調整測試腳本」或從草稿入口接續時，先確認是否調整。確認後從正式版本開新草稿，或接續目前草稿。
- 概覽提供「編輯說明與背景」，可修改目前正式版本的 Markdown 說明與背景。標籤可手動新增、移除或從目前版本的 AI 建議挑選。這些操作直接儲存測試資訊，沿用原腳本、版本與驗證報告。
- 正式執行紀錄與 AI 撰寫／草稿驗證分開；後兩者呈現在編輯對話。
- 通過的執行紀錄提供已保存的報告。失敗證據下載入口用於可查錯的未通過結果。
- 版本歷史依發佈順序由新到舊顯示。草稿列提供續編與刪除。每個已發佈版本都可開啟詳情，查看版本說明、完整腳本，以及與前一個已發佈版本的逐行差異。
- AI 產生的腳本發佈後，Workspace 內可從版本詳情查看當次編輯週期的使用者訊息與 Whippet 回覆。依對話順序唯讀顯示，長對話可分頁載入。
- 未曾發佈的一般測試在概覽顯示草稿入口。確認刪除草稿且任務資源回收完成後，將整筆測試移出 Workspace 並回到預設畫面。先前已放棄且未曾發佈的一般測試也從清單移除。
- 刪除草稿須確認對話框，說明放棄本次修改與對話接續、不影響正式版本。活躍任務先取消並等終止，再完成放棄；失敗時保留草稿並可重試。歷史證據不連帶刪除。

## 新建／修改測試

整個右側為類似 ChatGPT 的對話工作區：持久訊息、輸入區、AI／排隊狀態、腳本預覽、驗證結果、唯讀監看與報告卡片。必要動作以卡片按鈕提供，不要求 QA 輸入特殊指令。離開／重開可恢復已保存內容；未送出文字與進行中操作提供離開保護。

- 新建直接進入對話；Test 名稱／說明可在對話中收斂，不以完整表單作前置門檻。
- 無草稿時，從目前正式版本建立編輯週期，提供完整腳本、版本說明與背景摘要。
- 有草稿時，接續同一編輯週期，提供草稿完整腳本、該週期對話摘要及近期訊息；完整歷史可按需取用。
- 修改既有測試時，同時提供測試名稱、來源版本背景，以及目前草稿已有的驗證結果。大腳本超過模型容量時，AI 可按固定 revision 分頁讀取。
- AI 在操作前先比對既有腳本與測試目的。同一目的下可調整步驟、資料或檢查項目。若需求改成另一個主要流程、功能或預期結果，AI 應簡短說明差異並建議另開測試，本輪只回覆對話。意圖不清楚時先追問。
- 另開測試的建議下方提供「放棄草稿並新增測試」與「繼續調整」。確認放棄後，在同一 Workspace 建立新測試，將觸發建議的需求原文送為新對話的第一則訊息，依既有流程回收原草稿。原測試未曾發佈時，回收後會將它移出 Workspace。選擇繼續調整會保留原草稿與對話，並回到輸入區。
- 每輪均提供 Workspace 背景與範圍快照，機密只傳引用；等待使用者時釋放 Worker。
- Server 在排入 author 任務或交給 MCP Agent 前檢查當輪意圖。接受測試規劃、撰寫、執行、除錯及測試相關的 Workspace 設定。離題、混入額外任務或要求繞過權限的訊息會直接拒絕，意圖不明時請使用者補充。
- 驗證是真實 Run，狀態由 Server 提供；AI 文字不可代替測試通過或報告就緒。
- 編輯中按「開始監看」，在目前對話內顯示該 Run 的唯讀即時畫面。關閉監看面板後，Run 繼續執行。
- 通過後 AI 依實際腳本、對話及該次驗證證據產生 Markdown 版本說明、背景摘要，以及最多五個標籤建議。版本說明以一句變更重點開頭，供版本歷史顯示，內文涵蓋目的、前置條件、步驟、檢查結果與限制。摘要與建議保存到版本，說明與背景供下次 Agent 使用。使用者可在概覽採用需要的標籤。
- 摘要失敗可獨立重試，不重跑未改變的成功驗證；腳本／驗測設定改變須重新驗證。QA 看過摘要及報告後明確確認發佈，AI 不自動發佈。
- 對話內修復正式失敗只更新草稿，不改寫正式版本。

## Workspace 對話設定與多工作區

支援建立、切換與修改多個 Workspace，目前均為 Superadmin。每個 Workspace 保存名稱、驗測目的、範圍／排除事項、多組網站（名稱、用途、origin）、必要相依服務、登入角色／方式、非機密背景摘要、預設 URL 與執行逾時。

- 建立時先訪談，使用者確認初始目標網站後才探索；未確認前禁止瀏覽探索。
- AI 詢問登入與必要前置資訊，提出結構化設定提案；QA 確認後才啟用／更新設定。取消提案不覆寫現行設定。
- 修改時帶入舊設定與背景；設定對話與測試對話分開。設定提案使用 revision 衝突檢查。
- 目標網站與登入／API／CDN 等必要相依服務分開；相依服務不是可任意驗測的目標。新增範圍由使用者確認，AI 不能自行放寬。
- AI 探索、草稿自試、正式驗證與已發佈測試均依 Server 固定的核准範圍。AI、手動與舊版腳本共用出站限制。手動腳本在未確認網站時可驗證本機 HTML 等離線內容。既有測試需要新增網站時，先由使用者在 Workspace 設定確認，再接續草稿取得新的快照。
- 登入資料透過專用機密欄位收集，密碼／Token／cookie／storageState 不進模型或一般對話。允許 AI 讀取 Workspace 登入後頁面內容並持續探索、操作與監看。登入敏感輸入期間遮蔽，完成後恢復必要觀察。保留原生報告並遮蔽機密欄位與已知值。腳本只可透過本次任務授權使用 Workspace 登入角色。
- 平台權限尚不做 RBAC 介面，但測試、對話、執行、附件及機密皆以 Workspace 範圍讀寫，不可跨工作區引用。
- 不包含 Workspace 刪除、複製或多人協作功能。

## Worker skill-set

由 Server 指定對話類型、skill 版本及允許工具；Worker 載入對應的小型 skill，不建通用外掛平台。

| Skill | 輸入與交付 |
| --- | --- |
| Workspace 建立／修改 | 舊背景、設定提案與近期對話；受限探索、追問、輸出設定提案 |
| 測試建立／修改 | Workspace 快照、來源版本摘要、當前完整腳本與編輯週期對話；輸出候選草稿與驗證要求 |
| 驗收摘要 | 通過的 revision、完整腳本、對話背景與實際結果；輸出說明、背景摘要與建議標籤 |

Skills 共用既有 Playwright 操作 recipe。完整歷史持久保存，預設只傳摘要＋近期對話，按需檢索。網頁內容、對話資料與工具輸出不得變成系統指令。發佈資格、網站限制、機密存取與任務去重由程式強制執行。

## 最小驗收

一條主要流程：建立 Workspace 與確認範圍 → 以合成帳密探索 → 對話建測試 → 真實驗證與監看 → 摘要 → 人工發佈 → 一般模式正式執行 → 重開草稿續編 → 刪除草稿。另以第二個 Workspace 做一次資源／機密隔離檢查。

針對新風險驗證過期 revision／摘要無法發佈、刪除後晚到結果無法復活草稿、手動與 AI 腳本無法連上未核准站點、離題或模仿工具呼叫的內容無法觸發作者任務，以及機密遮蔽。

## 腳本來源

Server 依實際寫入路徑記錄腳本來源，並固定於驗證、版本及 Run。腳本可使用迴圈、自訂函式與 Playwright 的頁面 evaluate。一般模式腳本唯讀，工程師從編輯模式的進階入口修改。
