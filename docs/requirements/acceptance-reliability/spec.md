# 整合驗收與部署證據

維護者需要知道每次黑箱驗收測到哪一版；自架操作者需要知道遠端執行與監看各自在什麼環境通過。本輪沿用 [WLA-4 runner 與定向案例](../../../scripts/test/wla4-acceptance.md)，範圍限於驗收工具、環境實測與文件入口。若實測發現產品缺陷，保留失敗證據並另列修正任務。

## 驗收情境

| 編號 | 操作 | 通過條件 |
| --- | --- | --- |
| A1 同源建置 | 在獨立 checkout 為前後端各加入一個可辨識的未提交變更，分別以指定 commit 和目前工作目錄建置並執行定向案例。 | Web、Server、Manager、Worker 共用同一份凍結來源。commit 模式兩個變更皆未出現，工作目錄模式兩者皆出現。結果記錄模式、基準 commit、來源內容摘要與各產物識別，重試可辨識來源是否相同。工作目錄快照涵蓋建置所需的新增檔，排除機密與既有建置產物。 |
| A2 登入期間監看 | 在正式觀看端連續觀測測試站登入，先以錯誤帳密失敗，再修正並成功。測試頁於敏感區間呈現可辨識的合成標記。 | 以未遮蔽的測試畫面確認偵測器能找到標記。核對觀看端收到的每張影格，兩次敏感區間均無標記，區間前後均看得到正常畫面。記錄區間、影格數、遮蔽或停送行為及恢復結果；觀看端未連上或取樣中斷時無法判為通過。 |
| A3 跨主機執行 | 在不同網路的 Linux Server 與 Mac 端 Manager／Worker，從正式入口執行一筆已發佈測試。 | 同一 Run 可對上 Manager 接單、Worker 結束與使用者開啟報告。記錄版本、拓樸與 Run ID。 |
| A4 跨 NAT 監看 | 在 A3 拓樸啟動 LiveView 並透過 TURN 中繼。 | 觀看端收到持續更新的畫面，WebRTC 統計顯示使用中的候選配對至少一端為 relay。記錄配對類型、時間及接收影格增量。A3、A4 各自記錄結果；缺主機或 TURN 環境時列出缺項。 |
| A5 任務入口 | 由 README 進入實作計畫。 | 第一個進度摘要能查到最近完成事項、下一個可執行任務、環境需求與證據連結；分工表依任務編號指派，進度僅更新於實作計畫。 |

驗收紀錄引用可重跑的指令及去識別化結果。歷史本機 WLA 驗收作為基準，A2 到 A4 各自補上實測證據。
