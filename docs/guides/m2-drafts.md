# 草稿、驗證與發佈

M2 的操作順序是：新增測試 → 編輯草稿 → 儲存 → 執行驗證 → 查看報告 → 確認發佈。既有測試亦可開啟草稿修改。

一個測試只有一份目前草稿。儲存使用 revision 檢查；若另一個頁面已更新，應重新載入後再修改。每次修改都需要重新驗證，舊 revision 的成功結果不能用來發佈新內容。

發佈必須同時滿足目前 revision 驗證成功、報告已上傳及使用者明確確認。正式執行使用當時已發佈版本，之後修改草稿不改變版本內容或歷史執行快照。未發佈的測試可以驗證草稿，但不能正式執行。

## 併發與取消

在本機 `deploy/.env` 設定 `MAX_WORKERS=2`（可用範圍 1–64，預設 1），再依本機指南重建／重啟 Manager。不要把 AI key 注入一般測試 Worker。

超過上限的任務保留在 Server FIFO 佇列。取消排隊中的任務立即結束；執行中的取消須等待 Manager 停止及移除容器。清理失敗會保留名額，不會一邊留下舊容器一邊啟動新任務。

Server 與 Manager 斷線期間，既有執行不會立即重派；重連透過 heartbeat、attempt ID 與持久 journal 對帳。不要刪除 `deploy/.local/runner` 以嘗試解除排隊，這會丟失去重與回收紀錄。
